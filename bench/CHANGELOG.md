# bench changelog

Every change to the spec or the harness after candidates were measured. Thresholds, gates and checks of `foundation/evaluation.md` are never changed here. Each entry is applied uniformly to all candidates and was made before the candidates were re-evaluated.

## 2026-10-08, step 4c (harness fixes after the first candidate pass)

| # | Change | Why | Effect |
|---|---|---|---|
| 1 | `scripts/render_reference.py` renders every correctness / table_unicode case in a fresh interpreter (one process per case, 8 in parallel); goldens regenerated | Rich caches a `Style`'s ANSI codes on first use whatever the color system (`Style.parse` is `lru_cache`d, `Style._ansi` is filled on first render), so rendering all cases in one process made 28 of 210 goldens depend on which color depth ran before them (18 progress, 4 panel, 3 table, 2 tree, 1 style). Found independently by four candidate forks | 28 files of `golden/correctness/` change; the 12 `table_unicode` goldens and all other goldens are unchanged. The per-candidate `reference_quirk` exclusions are dropped (verified unnecessary, see `PILOT-RESULTS.md`) |
| 2 | `scripts/api_surface.py` and `scripts/docs_coverage.py` run rustdoc with `--lib`; `api_surface.py json` names its output by the lib target (resolved with `cargo metadata`, so package `rs-rich` gives `rich.json`); `docs_coverage.py` runs `cargo test --doc` (the lib's doctests) in a pristine copy of the published crate source instead of `cargo test --doc -p` (cargo refuses `-p` for non-workspace dependencies) and reports ignored doctests | the scripts failed on crates with a bin target and on registry dependencies; candidates worked around it by hand | docs and API numbers are produced by the scripts for every candidate |
| 3 | `spec/tasks.json` t06 statement now describes line 1 `Deploy ok in 3.2s` and line 3 ` FAIL  retry in 5s` exactly as the embedded target shows them (the old statement omitted the plain ` in ` and the plain space); `spec/tasks/t06-markup.md` regenerated | `task_defect`: statement and target disagreed. The target is unchanged | t06 solutions written to the target remain valid |
| 4 | `spec/tasks.json` t08 statement: "bold is allowed to remain" becomes "bold stays: NO_COLOR removes color only, not text attributes"; `spec/tasks/t08-env.md` regenerated | `task_defect`: the check requires bold under `NO_COLOR=1` (Rich Python keeps it; the NO_COLOR convention forbids color only), the statement said it was optional. The check is unchanged | the t08 `no_color_tty` run stays a real failure for crates that drop bold |
| 5 | `scripts/speed.py verify S3` also requires that the stream shows at least 900 of the 1 000 expected frames (`frames_matched`: terminal-emulator replay, the first task's counter read after each cursor-up, compared with the values `(100 f + 7) // 8`; Python Rich 1 000, `golden/speed/s3.frames.json`); `verify` returns a fourth element (note); `spec/speed.md` updated | the check compared only the final screen, so a candidate that never animates passed (`rich-rs` did until its adapter was forced into terminal mode). A first version counted distinct `N/12500` strings in the stripped stream and wrongly rejected `rich-rs`, which redraws only the changed digits; it was replaced before any number was published | S3 numbers only count for candidates that emit the frames the workload defines, however they redraw |
| 6 | Tests: golden isolation and the S3 frame check (full redraw matches, final-frame-only does not, changed-digits-only redraw matches) added to `tests/test_bench.py` | self-test of changes 1 and 5 | |
